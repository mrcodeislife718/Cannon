# Cannon Vision

## Product identity

Cannon is our general-purpose programming language.

Its design objective is to combine the approachability and expressiveness associated with Python, Ruby, and Perl with a path toward the reach and control associated with C.

The governing rules remain:

1. Easy things stay easy.
2. Powerful things remain possible.
3. Dangerous things are explicit.

## Primary comparison set

Cannon is our answer to lessons drawn from:

- Python
- Ruby
- Perl
- C

Cannon is not intended to clone any one of them. It should preserve what makes dynamic, expressive languages productive while avoiding the assumption that approachability must permanently exclude deeper control or systems reach.

## Strengths to preserve

- Low-friction syntax and ordinary application development.
- Fast path from idea to working program.
- Expressive general-purpose programming.
- Readability and discoverability.
- Progressive access to more control when developers need it.
- Compatibility with the broader Cannon ecosystem without depending on it for basic usefulness.

## Weaknesses to eliminate

Cannon should target recurring tradeoffs developers are normally forced to accept:

- approachability should not require permanent loss of control;
- power should not require needless ceremony;
- dangerous operations should not be hidden;
- language usability should not depend on an IDE or cloud service;
- the language should not become permanently identified with a bootstrap runtime such as Node.

## Independent ceiling

Cannon must be capable of succeeding as a language in its own right. Nova, Parallel, Plasma, Cadence, Sprout, Velocity, Chronos, Cortex, Cannon+, and Scout exist to extend the ecosystem around Cannon, not to reduce Cannon to a frontend syntax for other products.

## Ecosystem role

- Cannon+ extends Cannon with stricter typed/systems capabilities.
- Nova provides compiler and developer intelligence.
- Parallel provides Cannon's runtime path.
- Plasma opens foreign/native ecosystems.
- Cadence and Sprout provide first-party application frameworks.
- Velocity and Chronos extend development and production workflows.
- Cortex provides a deeply integrated engineering environment.

## Architectural invariant

**Cannon remains the language. Do not narrow it into an internal DSL, compiler frontend, IDE language, or framework-specific language for the sake of ecosystem simplification.**
